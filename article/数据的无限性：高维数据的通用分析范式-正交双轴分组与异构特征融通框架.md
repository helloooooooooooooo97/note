
> **摘要**：真实世界中的数据天然具有多样、多来源、高维度与大量缺失等特征，高维异构矩阵并非人为制造，而是业务系统汇聚信息后的必然形态。若将全量特征直接拼接为统一向量再建模，往往容易引发维度灾难、语义干扰与计算失效；更根本的问题是：如何把多源异构、残缺不全的数据合并起来，形成可对比、可分析的参照系。本文提出一种通用算法设计范式——**正交双轴分组与异构特征融通框架（Orthogonal Dual-Axis Grouping & Heterogeneous Feature Fusion Framework）**。该范式先在特征空间（列维度）做“外部分组”以解耦语义，再在样本空间（行维度）做“内部分组”以构建可比较的域；并在此基础上完成局部表征提取、跨域特征联立、多维度联合决策与逆向归因。框架还强调：在不改动核心算法的前提下，降低时间复杂度只有筛选与分组两条路，而外部分组使筛选更易落地。本文给出该框架的形式化定义，并以恶意加密流量检测等场景贯穿说明其设计思想与落地路径。

## 1. 核心问题、形式化定义与设计动机

### 1.1 现实场景为何不可避免地产生高维数据

在真实业务环境中，分析对象几乎从不以“干净、完整、低维”的理想表格出现。相反，数据天然具有以下四个特征，使得**高维异构矩阵成为不可避免的工作对象**：

1. **多样性（Diversity）**  
   同一实体会被多种形态的信息描述：数值统计、离散标签、文本、时序序列、图关系、指纹哈希等。这些信息并不共享统一量纲，却往往共同指向同一个预测目标。
2. **多来源（Multi-Source）**  
   数据来自不同采集链路与系统边界，例如流量探针、DNS 日志、终端指纹、威胁情报、资产台账、业务工单。来源越多，字段语义越分裂，对齐成本越高。
3. **高维度（High-Dimensionality）**  
   每新增一个数据源、一种探针或一类业务标签，特征列就会继续扩张。维度增长不是偶发事故，而是系统持续接入信息后的常态结果。
4. **大量缺失（Massive Missingness）**  
   真实样本极少拥有全字段观测。某些流没有域名，某些会话缺少指纹，某些主机没有资产标签，某些时间窗缺少完整统计。缺失不是噪声边角，而是数据本体的一部分。

因此，现实问题并不是“要不要处理高维数据”，而是：**在数据必然高维、必然异构、必然残缺的前提下，如何把它们合并起来做对比分析。**

这里的“合并”不是简单地把列拼在一起，而是要同时回答三件事：

- **对齐**：不同来源的字段如何落到同一实体（同一行）上；
- **可比**：合并后的特征在什么视角、什么边界下才有比较意义；
- **可用**：在大量缺失与高维噪声并存时，如何仍能稳定完成预测与归因。

以恶意加密流量检测为例：一条待判定会话可能同时关联 JA4/证书指纹、Flow/CIC 统计、五元组与时间戳、解析域名、内外网资产属性，以及威胁情报命中结果。这些信息分别来自不同系统，字段并不齐备，却都必须服务于同一个问题——该样本是恶意还是正常。若不解决多源异构数据的合并与比较问题，后续任何分类、聚类、降维或回归，都会建立在错误的参照系之上。

这正是本文框架的必要性所在：高维不是可选设定，而是真实世界的默认状态；正交双轴分组，正是为了在这种默认状态下，把“多源合并”转化为“可比较、可筛选、可计算”的分析结构。

### 1.2 核心任务与形式化定义

许多复杂系统建模问题，本质上都可以抽象为：**对高维数据矩阵中的每一行（即每一个样本实体）进行预测与推理**。

#### 形式化定义（Formal Definition）

给定高维异构特征矩阵：

$$X \in \mathbb{R}^{N \times D}$$

其中，$N$ 为样本数（行数），$D$ 为特征维度（列数）。需要强调的是，$X$ 在真实场景中通常还伴随大面积缺失，因而更接近“带缺失的高维异构观测”，而不是理想完备矩阵。矩阵第 $i$ 行对应第 $i$ 个待预测样本（如一条网络会话、一个用户节点或一次交易记录）：

$$x_i = [x_{i,1}, x_{i,2}, \dots, x_{i,D}] \in \mathbb{R}^D$$

算法目标是综合运用分类（Classification）、聚类（Clustering）、降维（Dimensionality Reduction）、回归（Regression）等机器学习与统计建模手段，学习映射函数：

$$f: \mathbb{R}^D \to \mathcal{Y}$$

并对每个样本给出预测：

$$y_i = f(x_i)$$

- **恶意加密流量检测场景**：每个样本 $x_i$ 对应一条加密网络流或主机会话，输出空间为二分类标签：

$$\mathcal{Y} = \{0, 1\}$$

其中 $y_i=1$ 表示恶意样本（Malicious），$y_i=0$ 表示正常样本（Benign）。
- **更一般的场景**：$\mathcal{Y}$ 也可以是连续标量（回归）、多类概率分布（多分类），或异常得分（无监督检测）。

### 1.3 传统方法的痛点与设计动机

正因为真实数据必然是多样、多来源、高维度且大量缺失的，传统做法——把全量异构特征直接拼接成统一向量，再送入单一全局模型——会在语义、比较、计算、筛选与归因等多个层面同时失效。下表对传统算法的核心痛点做系统归纳：

| 痛点维度      | 传统做法的具体表现                  | 导致的后果                  | 在恶意加密流量场景中的典型例子                      |
| :-------- | :------------------------- | :--------------------- | :----------------------------------- |
| **语义混淆**  | 身份、行为、环境等不同语义特征被强行拼进同一向量   | 不同量纲与物理含义互相干扰，关键弱信号被淹没 | JA4 指纹（离散哈希）与包长统计（连续数值）直接拼接后互相掩盖     |
| **维度灾难**  | 在全量高维空间 $D$ 上直接拟合 $f(x_i)$ | 样本稀疏、距离失效、模型不稳定、泛化变差   | 全量特征同时包含指纹、Flow/CIC、IP、域名后，全局距离几乎无意义 |
| **样本不可比** | 缺少统一局部基线，把异质样本放在同一参照系下比较   | 横向/纵向比较失真，异常判定阈值难以成立   | 内网主机与公网服务器共用同一流量基线，误报显著升高            |
| **缺失失控**  | 多源字段天然大量缺失，却仍被当作完备向量处理     | 填充失真、样本偏置、模型依赖伪完整信息    | 无域名会话与有域名会话被一视同仁送入同一全局模型             |
| **算法不适配** | 所有特征共用一套通用算法，无法按语义选择专属方法   | 算法与数据形态错配，局部结构难以被有效提取  | 流特征适合时序/分布分析，却被迫与域名 NLP 特征共用同一模型     |
| **筛选困难**  | 特征混杂，难以定义清晰、廉价的剪枝规则        | 无法在不改核心算法的前提下有效缩小数据规模  | 不知道该先按域名筛、还是按 IP 筛，剪枝容易误删关键样本        |
| **批次过大**  | 对全量 $N$ 做一次性重计算，缺少结构化分组    | 单批时间复杂度高，难以并行与增量处理     | 对全网会话统一做聚类/图计算，计算与内存开销爆炸             |
| **先验难融入** | 专家规则、威胁情报、专属小模型难以嵌入统一管线    | 业务知识与机器学习割裂，系统可扩展性差    | 恶意域名检测器、内外网规则无法自然进入全局端到端模型           |
| **归因失效**  | 输出多为黑盒分数或标签，缺少可下钻的结构       | 告警难解释、难溯源、难闭环优化        | 判定某流为恶意后，说不清是流量突变、指纹异常还是域名命中导致       |
| **扩展成本高** | 新增一类特征往往要重构整套特征工程与模型       | 迭代慢、维护成本高、线上风险大        | 新增证书/JA4 维度后，需要整体重训全局模型              |

可以看到，传统痛点并不只是“效果不好”，而是同时卡在 **可比性、可计算性、可筛选性与可解释性** 四条链路上；而其根源，正是回避了真实世界最基本的事实——**数据必然多样、多来源、高维度且大量缺失，必须先解决“如何合并后再对比分析”的问题**。尤其在工程侧，还有一个更硬的约束：**在不改动核心算法的前提下，如何降低时间复杂度**——这也是本文引入分组机制的重要动机之一。

为此，本文提出“正交双轴分组与异构特征融通”范式：**先按特征语义列做外部分组，再在各子空间内按样本行做内部分组**。


## 2. 核心哲学

正交双轴分组有两层目的：一层是语义层面的——**创建可比较的域**；一层是计算层面的——**在不改算法的前提下降低复杂度**。二者相互支撑。

### 2.1 分组是为了创建可比较的域

正交双轴分组的语义关键，不在于“如何切分”本身，而在于其目的：**在局部构建可比较的域（Domains of Comparability）**。

```
 原始高维异构空间                        正交双轴分组后
┌──────────────────┐               ┌─────────────────────────────────┐
│  全量特征向量 x_i │  解耦与分组   │ 局部域 1: 统一维度 + 同质边界    │ → 横向/纵向可比
│ (维度混淆/不可比) │ ───────────► ├─────────────────────────────────┤
└──────────────────┘               │ 局部域 2: 专属语义 + 局部基线    │ → 局部机器学习
                                   └─────────────────────────────────┘
```

#### 为什么原始空间“不可比”

在原始高维异构空间中，样本并不天然具有可比性。例如：

- 将“包长分布”（连续数值）与“JA4 指纹”（离散哈希）直接做距离计算，缺少统一物理尺度；
- 将“内网主机”与“公网服务器”放在同一全局流量基线下做异常检测，容易产生系统性误报。

#### 什么是可比较的域

正交双轴分组从两个层面先重建局部参照系：

1. **外部分组（列解耦）定义比较视角**：明确在何种物理或语义尺度上进行比较，例如“时序行为视角”或“环境拓扑视角”，并得到更干净的特征子空间 $X^{(k)}$。
2. **内部分组（行划分）形成组单元**：在该子空间上把样本划成组，并给出打标与聚合表征。

但这里必须再进一步：

- **组本身**已为内部样本提供干净分析域（如连通图组内可继续分析流样本）；
- 但**还不能**对子空间内全部组一锅端地做组间比较，还需要按业务维度把组再 batch 成更大的“域”。

外部分组让特征变干净；内部分组让组内样本可细分析；域则让组与组进入同一个干净的比较批次。形式化展开见第 4.4 节。

一旦形成域，域内各组之间、以及组与域基线之间，才具备：

- **横向可比性**：在同一域内比较离群程度；
- **纵向可比性**：与该域历史模式比较偏离程度。

此后，分类、聚类、降维、回归等方法才能在局部域中更准确、更稳定地发挥作用。

### 2.2 不改核心算法时，降复杂度只有两条路：筛选与分组

从计算角度看，若**不改动核心算法本身**（即不换更轻的模型、不改算法渐近复杂度级别），要降低时间复杂度，本质上只有两条路：

1. **筛选（Filtering / Pruning）**：直接降低参与计算的数据规模，把无关、低价值或可提前排除的样本/特征剔除，使算法只在更小的有效集合上运行；
2. **分组（Grouping / Batching）**：不减少全量数据的存在，但降低**一个批次（batch）内**同时参与计算的数据规模，使原本对全量一次性计算的问题，转化为若干局部、可并行的小规模计算。

二者关系非常紧密：

- **分组是筛选的前置条件**：全量异构特征混在一起时，筛选规则往往难以定义——不知道按哪一列筛、按什么阈值筛、筛完是否还保留关键信号；
- **外部分组之后，筛选才更方便**：一旦按语义把特征列切开，就可以在单一语义子空间内制定清晰、廉价的筛选策略。例如：先在域名子空间筛掉明显正常域名，再在流量子空间对剩余样本做重计算；或先在 IP 子空间筛掉内网无关流量，再对外网会话做细粒度检测；
- **内部分组进一步压缩单批次规模**：即便筛选后仍有大量样本，也可按局部域分批处理，使单次聚类、图计算或分类器推理只面对一个小批次，而不是全量矩阵。

因此，正交双轴分组不仅服务于“可比”，也服务于“可算”：**外部分组让筛选变得可行，内部分组让批次规模变得可控；筛选与分组配合，才能在不改核心算法的前提下有效降低时间复杂度。**

```
不改核心算法 f(·)
        │
        ├─► 筛选：缩小有效数据规模 N / D
        │         ↑
        │         │ 外部分组后，筛选规则更清晰、成本更低
        │         │
        └─► 分组：缩小单批次规模（batch size）
                  ↑
                  │ 内部分组把全量计算拆为局部并行计算
```

## 4. 核心机制与案例分析

### 4.1 外部分组：划分视角非唯一，且决定后续建模上限

将全量特征按语义或业务视角划分为 $M$ 个子特征空间：

$$X = [X^{(1)}, X^{(2)}, \dots, X^{(M)}]$$

这里的关键在于：**外部分组不是唯一的**。同一套原始特征，可以从不同视角切分与组合；而不同切分方式，会直接决定内部分组能做什么、做到什么程度。

以流量分析为例：

- **视角 A（引入时序与拓扑）**  
  若将 `[时间戳, 源IP, 目的IP, 源端口, 目的端口]` 放入同一子空间 $X^{(1)}$，该空间同时保留时间信息与节点关联，内部分组便可在“1 分钟窗口”内构建连通图，并进一步做社区发现、图聚类或 GNN 表征学习。
- **视角 B（仅保留静态网络属性）**  
  若只将 `[IP, 端口]` 放入 $X^{(2)}$，且不引入时间戳，则该空间缺少时序动态关联，内部分组通常只能做静态属性划分，例如按网段规则区分“内网/外网”，或区分“公网服务/私网终端”。

因此，**外部分组不仅是特征切分，更是在定义局部可比较域的维度边界与语义上限**；同时，它也为后续筛选提供了清晰的操作面——先切列，再按列筛选，比在混杂全量特征上盲目剪枝更稳妥。

### 4.2 内部分组：在子空间中构建可比较样本域

在每个子特征空间 $X^{(k)}$ 中，对样本行独立划分，形成局部可比较域：

$$G^{(k)} = \mathrm{Partition}(X^{(k)})$$

内部分组不限于无监督聚类，凡是能在特定视角下建立同质性与比较基线的方法，都可以纳入：

- **聚类 / 图结构构建**：例如对流量子空间做 DBSCAN，或按时间切片构建连通图；
- **先验规则与边界分桶**：例如按 IP 网段规则划分为内网域与外网域；
- **专属检测器 / 分类器**：例如用恶意域名检测模型或威胁情报库，划分为恶意域名域与非恶意域名域。

这样做的好处主要有三点：

1. **建立局部参照系**：在同质组内形成统一统计基线，使比较从“全局无序”转为“局部有据”；
2. **压缩单批次计算规模**：把对全量 $N$ 的一次重计算，拆成对若干局部组的小规模计算，从而在不改核心算法的前提下降低单批时间复杂度；
3. **便于融合先验、筛选与小模型**：允许不同子空间分别采用规则、聚类或有监督检测器，并在组内做更精准的二次筛选。

### 4.3 组表征、行压缩与列特征重构，以及联合决策

完成外部分组与内部分组后，系统并不是停留在“原矩阵被切碎”的状态，而是会**再生成一张以“组”为基本分析单元的新数据表**。这张新表在**行方向通常实现压缩**；在**列方向则是特征重构**——维度不一定变少，甚至可能因聚合特征而变大。

#### 1. 从样本矩阵到组矩阵

记原始高维矩阵为：

$$X \in \mathbb{R}^{N \times D}$$

经外部分组得到第 $k$ 个子空间 $X^{(k)} \in \mathbb{R}^{N \times D_k}$（通常 $D_k < D$，因只保留该语义视角下的列），再经内部分组得到该子空间下的样本组集合：

$$G^{(k)} = \{g_1^{(k)}, g_2^{(k)}, \dots, g_{m_k}^{(k)}\}$$

其中每个组 $g_j^{(k)}$ 包含若干原始样本。若以组为新行、以组表征为新列，则可构造组级矩阵：

$$Z^{(k)} \in \mathbb{R}^{m_k \times d_k}$$

这里必须区分两个轴：

- **行**：从 $N$ 变为 $m_k$，一般减少；
- **列**：从子空间原始列 $D_k$ 变为组表征列 $d_k$，**$d_k$ 与 $D_k$（乃至 $D$）没有必然的“变少”关系**。

#### 2. 行压缩：为什么行数据一定减少（或至少不增）

内部分组把多个原始样本映射到同一个组。设组 $g_j^{(k)}$ 的成员集合为 $S_j^{(k)}$，则：

$$|S_j^{(k)}| \ge 1,\qquad \bigcup_j S_j^{(k)} \subseteq \{1,2,\dots,N\}$$

因而组数量满足：

$$m_k = |G^{(k)}| \le N$$

等号仅在“每个样本单独成组”的退化情形下成立；一旦出现同质合并（如多个会话归入同一指纹簇、同一内网域、同一连通图社区），就有严格压缩：

$$m_k < N$$

直观地说：

- 原始矩阵按“样本”记账，有多少样本就有多少行；
- 组矩阵按“可比较的域单元”记账，多个样本可共享同一行；
- 因此，**行压缩来自样本到组的多对一映射**，而不是简单删行。

这也解释了前文“分组降低单批次规模”的机制：后续算法面对的是 $m_k$ 个组，而不是 $N$ 个原始样本。

#### 3. 列特征重构：组特征向量的构成（维度可增可减）

对组 $g_j^{(k)}$，其组特征向量定义为：

$$z_j^{(k)} = \big[\; z_j^{(k),\mathrm{agg}}\;\big\|\; z_j^{(k),\mathrm{tag}}\;\big]$$

其中两部分的含义需要严格区分：

1. **组内聚合特征 $z_j^{(k),\mathrm{agg}}$（Internal Aggregated Features）**  
   由组内每个成员在该子空间下的原始特征聚合得到。即：先取组内样本在 $X^{(k)}$ 上的原始观测，再做均值、方差、分位数、频次熵、中心向量、直方图、图统计量等聚合。形式化写作：

$$z_j^{(k),\mathrm{agg}} = \mathrm{Agg}\big(\{x_i^{(k)} \mid i \in S_j^{(k)}\}\big)$$

   这部分回答的是：“这个组在内容上长什么样”——由组内原子特征汇总而来。  
   **关键点：聚合并不必然降维。** 对同一组原始列，可以派生出大量聚合量（多阶矩、多百分位、多窗口统计、多图指标等），因此：

$$\dim\big(z_j^{(k),\mathrm{agg}}\big) \ge D_k$$

   甚至在丰富聚合下显著大于 $D_k$。列特征变多，在这里是正常现象。

2. **内部分组打标特征 $z_j^{(k),\mathrm{tag}}$（Internal-Partition Tags on the External Subspace）**  
   这里的“打标”不是任意元数据，而是指：  
   **先经外部分组得到新的特征子空间 $X^{(k)}$，再在该子空间上执行内部分组 $\mathrm{Partition}(X^{(k)})$ 时，为每个组打上的划分标签。**

   也即打标发生在“外部分组所形成的新特征空间”之上，标签本身就是内部分组的输出：

$$z_j^{(k),\mathrm{tag}} = \mathrm{Label}\big(g_j^{(k)};\; \mathrm{Partition}(X^{(k)})\big)$$

   例如：
   - 在 IP 子空间上做内网/外网划分 → 打标为“内网”或“外网”；
   - 在域名子空间上跑恶意域名检测器 → 打标为“恶意域名组”或“非恶意域名组”；
   - 在时序/五元组子空间上做连通图社区发现 → 打标为某个社区 ID；
   - 在流统计子空间上做聚类 → 打标为某个行为簇编号。

   这部分回答的是：“在该外部分组视角下，内部分组把这个组划到了哪一类可比较边界”。

因此，**组的列特征 = 该外部分组子空间下的组内聚合特征 + 该子空间上内部分组给出的打标特征**。前者刻画组的内容形态，后者刻画组在当前划分下的归属。

组级列维度写为：

$$d_k = \dim\big(z_j^{(k),\mathrm{agg}}\big) + \dim\big(z_j^{(k),\mathrm{tag}}\big)$$

于是有三种常见情形：

- **$d_k < D_k$**：聚合较简，主要做摘要；
- **$d_k \approx D_k$**：聚合维度与原子列大致相当；
- **$d_k > D_k$（甚至可能接近或超过原全量 $D$）**：聚合特征族很大时，列会变多。

所以，列侧的准确表述应是**特征重构（Feature Reconstruction）**，而不是必然的列压缩：外部分组决定“在哪组原子列上工作”，内部分组决定“如何打标成组”，聚合则可能把这些原子列**展开**为更丰富的组级特征。

#### 4. 灵活性：不同外部分组 × 不同内部分组 → 不同组表征

组表征 $z_j^{(k)}$ 并不是唯一的。正因为外部分组视角可选、内部分组策略也可选，同一份原始矩阵 $X$ 可以导出多套截然不同的组矩阵：

$$Z^{(k)} = \Phi\big(X;\; \mathrm{External}_k,\; \mathrm{Partition}_k,\; \mathrm{Agg}_k\big)$$

其中：

- $\mathrm{External}_k$：外部分组如何切列，决定新特征空间 $X^{(k)}$；
- $\mathrm{Partition}_k$：在该空间上如何内部分组，决定组的边界与打标 $z_{\mathrm{tag}}$；
- $\mathrm{Agg}_k$：组内如何聚合，决定内容表征 $z_{\mathrm{agg}}$。

任一环节改变，都会得到不同的 $Z^{(k)}$。例如：

| 外部分组视角          | 内部分组策略      | 得到的组表征侧重           |
| :-------------- | :---------- | :----------------- |
| `[时间戳, 五元组]`    | 1 分钟连通图社区发现 | 社区打标 + 图/时序聚合特征    |
| `[IP, 端口]`      | 内外网规则划分     | 内外网打标 + IP/端口侧聚合特征 |
| `[域名相关列]`       | 恶意域名检测器     | 恶意/非恶意打标 + 域名侧聚合特征 |
| `[Flow/CIC 统计]` | 行为聚类        | 簇编号打标 + 流统计聚合特征    |

这正是算法灵活性的核心：**不是只有一套固定组表征，而是可以通过组合不同的外部分组与内部分组，按任务需要生成多套可比较、可融通的组级表示。**

#### 5. 行列变化关系一览

| 方向 | 原始对象 | 分组后对象 | 变化机理 | 结果 |
| :--- | :--- | :--- | :--- | :--- |
| **行** | 原始样本行 $N$ | 组行 $m_k$ | 内部分组把多个样本映射为同一个组单元 | **一定不增**：$m_k \le N$（通常 $m_k < N$） |
| **列** | 子空间原子列 $D_k$ | 组表征列 $d_k$ | $z_{\mathrm{agg}}$ 可派生大量统计量；$z_{\mathrm{tag}}$ 来自该子空间上的内部分组打标 | **可增可减**：$d_k$ 未必小于 $D_k$ 或 $D$ |
| **表示单元** | 样本向量 $x_i$ | 组向量 $z_j^{(k)}=\big[z_j^{(k),\mathrm{agg}}\,\|\,z_j^{(k),\mathrm{tag}}\big]$ | 子空间内聚合 + 子空间上内部分组打标 | 形成以组为行的新矩阵 $Z^{(k)}$；且随分组方案而变 |

可示意如下：

```
原始高维矩阵 X (N × D)
        │
        ▼ 外部分组：形成新特征空间 D → D_k
子空间矩阵 X^(k) (N × D_k)
        │
        ▼ 内部分组：在该新特征空间上划分并打标
样本组 {g_j^(k)}  +  打标 z_tag = Label(Partition(X^(k)))
        │
        ▼ 组表征构造（列特征重构，维度可增可减）
组矩阵 Z^(k) (m_k × d_k)
        │
        ├─ 列特征 = 组内聚合特征 z_agg  （可能很多）
        │            + 内部分组打标特征 z_tag
        └─ 行单元 = 组（多个原始样本的压缩结果）

说明：更换 External / Partition / Agg，会得到另一套 Z^(k)
```

#### 6. 仍保留的微观层：组表不等于丢弃溯源

需要强调：组矩阵 $Z^{(k)}$ 是给后续域内比较、筛选与决策用的**工作表**；原始样本在组内的微观特征仍可保留，用于下钻归因。也即系统同时持有：

1. **微观原始特征**：组内每个样本在子空间中的细粒度信息，服务溯源；
2. **宏观组表征**：$z_j^{(k)}=\big[z_j^{(k),\mathrm{agg}}\,\|\,z_j^{(k),\mathrm{tag}}\big]$，服务进入域后的比较与联合推理。

但要真正进入稳定的比较与推理，还需要下一步：**把组再按维度 batch 成域**。

### 4.4 从组到域：再次 batch，创造干净的分析环境

外部分组之后，新的特征空间 $X^{(k)}$ 相比原始全量空间已经干净许多：语义更齐、量纲更一致、可用算法也更明确。但即便如此，**仍然不能默认对 $G^{(k)}$ 中的全部组一起做分析**。

原因很直接：组与组之间，若缺少共同的业务边界，依然不可比。例如同一流量子空间里，“办公网某台 PC 在工作日 10 点的短连接组”与“机房服务器在凌晨的大文件传输组”，即使特征列已经干净，也不应放进同一个参照系里比离群。

因此，有了组之后，分析实际上沿着两个方向展开：

1. **向下看组内**：组本身就是为内部样本提供的干净分析域；
2. **向上看组间**：再按域键把组 batch 成更大的可比较集合。

二者都叫“创造干净环境”，但作用对象不同。

#### 0. 组的本质：为内部样本提供干净的分析域

先澄清组本身的角色。内部分组得到 $g_j^{(k)}$ 后，组内成员集合为：

$$S_j^{(k)} = \{ i \mid x_i \text{ 被划入 } g_j^{(k)} \}$$

此时，组 $g_j^{(k)}$ 对内部样本而言，就是一个**已洗净边界的局部分析域**：后续不应再拿全量子空间甚至全量原始矩阵去做细分析，而应把分析限制在 $S_j^{(k)}$ 内。

形式上看，组内工作对象是：

$$X^{(k)}_{g_j} = \{ x_i^{(k)} \mid i \in S_j^{(k)} \}$$

在这个局部集合上，可以继续做更细的分类、聚类、排序、路径分析或异常定位。例如：

- 按连通图完成内部分组后，先得到某个连通分量/社区作为组；
- 然后在该组内，对内部的流样本做进一步分析：关键边识别、主路径提取、异常流定位、会话角色划分等。

也就是说：

> **组 = 面向组内样本的干净分析域。**  
> 外部分组洗净了特征视角；内部分组则进一步洗净了“哪些样本可以放在一起细看”。

没有这一步，组内细分析会重新掉回异质样本混杂的环境；有了这一步，组内算法才有稳定边界。

#### 1. 形式化：域是组上的二次 batch

在组已经为内部样本提供干净环境之后，还要处理另一件事：组与组之间如何比较。设子空间 $k$ 上已得到组集合 $G^{(k)}$ 与组表征矩阵 $Z^{(k)}$。再定义一个**域键（Domain Key）**函数：

$$\kappa: G^{(k)} \to \mathcal{V}$$

其中 $\mathcal{V}$ 是域键取值空间。对任意键值 $v \in \mathcal{V}$，定义域：

$$\Omega^{(k)}(v) = \{ g \in G^{(k)} \mid \kappa(g) = v \}$$

于是，全量子空间上的组被重新组织为互不相交的分析批次：

$$G^{(k)} = \bigcup_{v \in \mathcal{V}} \Omega^{(k)}(v)$$

一个域 $\Omega^{(k)}(v)$ 的实际含义是：

> **在外部分组已洗净的特征空间里，再按业务维度 $v$ 截取出的一个 batch；该 batch 内的所有组，构成可比较集合。**  
> 相对地：**组面向样本，域面向组。**

对应的域内工作矩阵为：

$$Z^{(k)}_{\Omega(v)} = \{ z(g) \mid g \in \Omega^{(k)}(v) \}$$

后续的组间基线估计、异常评分、分类或回归，原则上都应在 $Z^{(k)}_{\Omega(v)}$ 上运行，而不是在整张 $Z^{(k)}$ 上盲目全局比较；而组内细分析，则应在 $X^{(k)}_{g_j}$ 上运行。

#### 2. 典型例子：`ip × flow:type × time:hour`

取域键为笛卡尔组合：

$$\kappa(g) = \big(\mathrm{ip}(g),\; \mathrm{flow\_type}(g),\; \mathrm{hour}(g)\big)$$

则某一个具体域可以是：

$$\Omega = \Omega^{(k)}\big(\mathrm{ip}=10.1.2.3,\; \mathrm{flow\_type}=\mathrm{https},\; \mathrm{hour}=10\big)$$

此时：

- 外部分组已保证比较发生在相对干净的特征视角（如流统计子空间）中；
- 内部分组已把样本压成组，并给出聚合特征与打标；
- 域键再把“同一 IP、同一流类型、同一小时”的各组收进同一个 batch。

这个域内所有组构成的可比较集合，其业务含义就是：

> **单个 IP 在特定流类型、特定小时下的历史基线分析环境。**

当前组相对该域内历史组分布的偏离，才是有意义的异常信号；若把该 IP 的 https/10 点行为，拿去和别的 IP、别的协议、别的时段混比，基线就会被污染。

#### 3. 层级关系：样本 → 组（组内域）→ 域（组间域）

三者不可混用，且“域”在这里有两层含义：

| 层级 | 符号 | 由什么产生 | 干净环境面向谁 | 典型分析 |
| :--- | :--- | :--- | :--- | :--- |
| **特征子空间** | $X^{(k)}$ | 外部分组 | 选定语义视角 | 为后续分组提供洗净的特征列 |
| **组** | $g_j^{(k)}$，$X^{(k)}_{g_j}$ | 在 $X^{(k)}$ 上内部分组 | **组内样本** | 连通图组内继续分析流样本、路径、异常边 |
| **域** | $\Omega^{(k)}(v)$ | 按域键 $\kappa$ 对组再 batch | **组与组之间** | 如单 IP 历史基线下比较各组偏离 |

可写成双向分析链：

$$\text{Sample } x_i \xrightarrow{\mathrm{Partition}} \text{Group } g_j^{(k)} \xrightarrow{\kappa} \text{Domain } \Omega^{(k)}(v)$$

- **向下**：在 $g_j^{(k)}$ 内对 $X^{(k)}_{g_j}$ 做细分析（组 = 样本的干净域）；
- **向上**：在 $\Omega^{(k)}(v)$ 内对各组表征 $z(g)$ 做比较（域 = 组的干净 batch）。

#### 4. 域上的比较运算（形式）

在域 $\Omega^{(k)}(v)$ 内，可定义基线与偏离。例如设域基线为：

$$\mu_{\Omega} = \mathrm{Baseline}\big(\{z(g) \mid g \in \Omega^{(k)}(v)\}\big)$$

对域内某一组 $g_*$，定义相对域的偏离得分：

$$s(g_*;\Omega) = \delta\big(z(g_*),\; \mu_{\Omega}\big)$$

其中 $\delta$ 可以是距离、残差、密度分数或分类器输出。于是“是否异常”不再相对全局，而相对该域：

$$\hat{y}(g_*) = \mathbb{I}\big[s(g_*;\Omega) > \tau_{\Omega}\big]$$

这正是“单个 IP 历史基线分析”的形式骨架：$\Omega$ 固定了 IP（及流类型、小时）边界，$\mu_{\Omega}$ 是该边界下的历史形态，$s$ 衡量当前组是否偏离。

#### 5. 域键本身也可灵活组合

与外部分组、内部分组一样，域键 $\kappa$ 不是唯一的。不同任务可选择不同 batch 维度，从而得到不同的可比较集合：

| 域键 $\kappa$ | 域内可比较集合的含义 |
| :--- | :--- |
| `ip × flow:type × time:hour` | 单 IP、同流类型、同时段的历史基线 |
| `ip × dst_domain` | 单 IP 访问同一域名的行为基线 |
| `subnet × service_port × weekday` | 网段级、同服务、同工作日模式基线 |
| `device_fingerprint × hour` | 同设备指纹在同时段的行为基线 |

因此，完整灵活性来自三层可组合：

$$\text{分析方案} = (\mathrm{External},\; \mathrm{Partition},\; \mathrm{Agg},\; \kappa)$$

换外部分组，换的是特征视角；换内部分组，换的是组边界与打标；换域键，换的是**哪一批组被放进同一个干净分析环境**。

#### 6. 示意

```
子空间 X^(k)（已相对干净）
        │
        ▼ 内部分组
组 g_j^(k)
        │
        ├─► 向下：组内干净域 X^(k)_{g_j}
        │         例：连通图组内继续分析流样本 / 路径 / 异常边
        │
        ▼ 按域键 κ 再次 batch（组间）
┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
│ Domain Ω(v1)     │  │ Domain Ω(v2)     │  │ Domain Ω(v3)     │
│ 例: IP=A, https, │  │ 例: IP=A, dns,   │  │ 例: IP=B, https, │
│     hour=10      │  │     hour=10      │  │     hour=10      │
│ 域内各组可比较    │  │ 域内各组可比较    │  │ 域内各组可比较    │
│ → 单IP历史基线   │  │ → 另一干净环境   │  │ → 另一干净环境   │
└──────────────────┘  └──────────────────┘  └──────────────────┘
```

一句话收束：

> **外部分组洗净特征视角；组为内部样本提供干净分析域；域再按维度给各组分配 batch，使组间比较也发生在干净环境中。**

### 4.5 跨域交互、联合决策与逆向归因

有了域之后，跨视角融通也更自然：不同外部分组方案下的域，可以互相提供先验。例如 IP 视角下某个域给出的“该主机在工作时段的正常画像”，可作为流统计视角下对应域的基线上下文。

在联合决策阶段，各子空间先在各自域内基于组表征给出单维评估，再由全局融合器通过加权、决策树、逻辑回归或图推理等方式组合。对落入某些组的原始样本 $x_i$，最终给出：

$$y_i = f(x_i)$$

在恶意加密流量场景中，可标定为：

$$y_i \in \{0: \mathrm{Benign},\ 1: \mathrm{Malicious}\}$$

当模型判定某样本 $x_i$ 为恶意（$y_i=1$）时，可沿正交结构回溯：

1. **外向归因**：定位主要贡献来自哪些特征子空间（如流量突变、域名命中黑名单）；
2. **域归因**：定位异常发生在哪个域 batch（如哪个 IP × 流类型 × 小时）；
3. **内向归因**：继续下钻到该域内的具体组与样本实体（如某连通图节点或某事件切片）。

由此，预测结果不再只是一个标签，而能对应到“哪一类特征、哪一个域、哪一组样本、哪一个实体”共同促成了判定。

---

## 5. 总结

该框架可概括为：

> **外部分组（洗净特征视角） → 内部分组（生成组与打标） → 按域键 batch（创造可比较环境） → 域内学习与跨域融合 → 逆向归因**

其中，计算侧的硬约束始终成立：

> **在不改动核心算法的前提下，降复杂度只有筛选与分组两条路；而外部分组之后，筛选才更方便。**

而比较侧的关键约束是：

> **$X^{(k)}$ 变干净，不等于全部组可一起分析；必须再按维度把组 batch 成域，域内各组才构成可比较集合。**

| 分析维度 | 传统全量特征拼接 | 正交双轴分组框架 |
| :--- | :--- | :--- |
| **形式化目标** | 直接在全量高维空间拟合 $f(x_i)$ | 将 $X$ 拆为子空间，经组与域两级组织后再建模 |
| **比较参照系** | 缺少统一基线，全局“不可比” | 外部分组洗净视角，内部分组成组，域键 batch 后形成可比较集合 |
| **划分灵活性** | 通常不做结构化划分，或划分方式单一 | External / Partition / Agg / $\kappa$ 均可组合替换 |
| **内部分组手段** | 主要依赖单一全局模型 | 可混合使用聚类、连通图、规则分桶与专属分类器 |
| **域的作用** | 无清晰 batch 边界 | 如 `ip × flow:type × time:hour`，支撑单 IP 历史基线等干净分析环境 |
| **降复杂度路径** | 往往只能堆算力，或被迫改核心算法 | 筛选缩小有效规模，分组/域 batch 缩小单批次规模 |
| **计算与归因** | 计算开销大，结果难解释 | 局部并行计算，并可沿“列—域—组—实体”路径归因 |

综上，正交双轴分组并不只是一种特征工程技巧，而是对真实世界默认状态的回应：数据必然多样、多来源、高维度且大量缺失，必须先解决“如何合并后再做对比分析”。该框架同时服务“可比”与“可算”——先洗净特征视角，再生成组，再按域键创造干净分析环境，并在此基础上完成筛选、局部学习与全局融合。它既适用于恶意加密流量检测，也可推广到其他高维异构数据场景。
