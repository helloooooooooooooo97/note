# Risk 方向矩阵观察与选题建议

## 1. 最适合低算力的组合

### 弱/半监督 × flow

真实流量最常见的问题不是模型不够大，而是标签少、标签噪声、时间漂移和未知攻击。这个方向可以用 CIC-IDS2017、CSE-CIC-IDS2018、UNSW-NB15、IoT-23 等公开数据做。

可做题目：

> Label-Noise-Aware Semi-Supervised Network Risk Detection under Temporal Drift

### LLM × flow / network

不建议让 LLM 直接分类 raw packet。更有价值的是：

- 解释 NIDS 告警。
- 总结误报规则。
- 从历史错误中构建 experience library。
- 把 flow 特征翻译成安全分析员可读的推理链。
- 对多个模型输出做 risk triage。

可做题目：

> Retrieval-Augmented LLM Analyst for Explaining and Reducing False Positives in Flow-based NIDS

### 自监督 × packet/flow

适合做 representation learning。贡献点可以不是训练巨大模型，而是：

- 更好的 packet/flow tokenization。
- 跨数据集迁移。
- 少标签 fine-tuning。
- 对加密流量的协议语义建模。

可做题目：

> Protocol-Aware Self-Supervised Pretraining for Low-Label Encrypted Traffic Risk Detection

## 2. 更像顶会/强会的空白

### 多粒度一致性

现在很多工作分别处理 packet、flow、graph，但真实检测需要三者一致：

- packet 是局部证据。
- flow 是行为摘要。
- graph/network 是攻击路径和横向移动上下文。

潜在贡献：

> Cross-Granularity Consistency Learning for Network Risk Detection

### LLM 不是分类器，而是审计员

很多 LLM-NIDS 工作会尝试让 LLM 直接做分类，但风险是成本高、稳定性差。更好的定位是：

- explanation agent
- false-positive analyst
- rule generator
- incident summarizer
- evidence verifier

潜在贡献：

> LLM-as-Auditor for Network Intrusion Detection: Evidence-Grounded Explanation and Error Memory

### 在线/流式无监督

2026 的综述已经把 streaming、memory-aware、unsupervised NIDS 标成重要方向。可以做一个轻量系统：

- edge screening
- prototype memory
- drift detection
- analyst feedback

潜在贡献：

> Memory-Augmented Streaming Anomaly Detection for Network Risk under Concept Drift

## 3. 不建议优先做的方向

- 纯监督 flow classifier：容易变成换模型刷分。
- 直接用 GPT/Claude 分类网络流量：容易被 reviewer 认为不经济、不稳定。
- 只在单一老数据集上报告高 accuracy：NIDS 领域很常见，可信度不高。
- 只做 packet payload 分类：加密、隐私和部署限制会卡住实际意义。

## 4. 推荐主线

如果要和你前面的 Agent 兴趣结合，最值得押的是：

> **LLM/Agent 辅助的网络风险分析：模型负责检测，Agent 负责解释、验证、记忆和升级规则。**

这条线显卡要求低，能结合：

- risk detection
- LLM / agent
- weak supervision
- memory
- human-in-the-loop
- evidence-grounded explanation
